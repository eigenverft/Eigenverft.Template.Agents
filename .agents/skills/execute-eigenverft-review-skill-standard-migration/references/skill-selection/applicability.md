# 1.2 Applicability

**Responsibility:** Explain when this review skill is appropriate and when a different skill or action is needed.

During migration:
- Put a meaningful invocation condition in frontmatter `description`, consistent with repository activation conventions.
- Distinguish a review request from a request to implement, refactor, create, or maintain code.
- Identify meaningful exclusions and overlaps with related reviews; describe the intended review lens rather than trying to claim every code-quality task.
- Do not let this section silently decide the current review target or amend the user's limits.

**Result:** Activation is predictable, and the actual user request is interpreted later by Request Resolution.
