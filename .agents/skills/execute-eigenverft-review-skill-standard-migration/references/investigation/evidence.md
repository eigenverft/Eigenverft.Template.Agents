# 3.1 Evidence

**Responsibility:** Obtain sufficient relevant information for the review's objective and scope, within the defined authority.

During migration:
- Define what to inspect first and which additional sources can clarify actual behavior: implementations, callers, tests, configuration, requirements, revisions, and dependencies as relevant to the review type.
- Follow material interactions or alternative paths rather than inferring design from file names, directory shape, or isolated snippets.
- Distinguish direct observations, credible reports, assumptions, and unavailable evidence.
- Scale inspection to the target and purpose; avoid both an arbitrary tiny sample and a mandatory exhaustive file inventory where it adds no value.
- Keep evidence gathering separate from declaring an issue proven.

**Result:** The target skill supplies a grounded, repeatable way to understand its subject.
