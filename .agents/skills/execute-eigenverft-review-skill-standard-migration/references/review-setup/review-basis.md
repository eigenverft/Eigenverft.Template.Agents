# 2.8 Review Basis

**Responsibility:** Establish which requirements, guarantees, invariants, contracts, accepted standards, or evidence-backed design goals define a meaningful problem.

During migration:
- Explain which sources may establish the basis: documented specifications, observed interfaces, tests, valid state transitions, relied-upon behavior, or explicit user requirements.
- For reviews without a formal specification, allow proportionate reasoning from observable behavior, documented intent, and realistic change scenarios, clearly labeled as such.
- Separate a factual breach from an arguable improvement opportunity and from an imagined future requirement.
- If essential criteria are missing, require a limited or conditional conclusion rather than inventing normative rules.

**Result:** Evaluation can explain *why* a candidate matters under an identified criterion.
