# 2.5 Context / Revision — Bezugszustand bestimmen

**Responsibility:** Establish the relevant project/repository/revision and the technical or domain state to which conclusions apply.

During migration:
- Specify how the review agent identifies the available current state, relevant branch/diff/revision, language, environment, and contextual requirements when material.
- Distinguish directly observed behavior, documented intentions, and hypothetical change scenarios.
- Use tests, history, specifications, and design notes as contextual evidence where relevant and permitted; do not invent an absent roadmap or requirement.
- State when an unavailable or changing revision limits confidence in an observation.

**Result:** Readers can tell *which state* the claims concern.
